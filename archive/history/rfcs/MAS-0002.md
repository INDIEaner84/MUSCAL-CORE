# MAS-0002: Core Task Scheduler & Parallel Execution Layer

## 1. Motivation

MAS-0001 definiert capability-basiertes Routing, aber keine konkrete Scheduling-Strategie. MAS-0002 definiert den Scheduler als capability-aware, MREIL-driven und resource-aware Instanz, die Tasks auf verfügbare Worker verteilt.

## 2. Terminologie

| Begriff | Definition |
|---------|-----------|
| Task | Capability-gebundener Ausführungsrequest |
| Strategy | Scheduling-Modus (single/parallel/cascade/ensemble/dag) |
| Worker | Ausführungsinstanz mit deklarierten Capabilities |
| Schedule | Zuordnung Task → Worker mit Cost-Score |

## 3. Systemmodell

Der Scheduler sitzt zwischen Compiler (MAS-0004) und Runtime (MAS-0005):

```
MPIR Graph → Scheduler → Schedule Plan → Runtime Execution
```

## 4. Scheduling Strategies

| Strategy | Beschreibung | Use Case |
|----------|-------------|----------|
| single | Ein Worker führt sequenziell aus | Kleine Tasks |
| parallel | Mehrere Worker gleichzeitig | Unabhängige Tasks |
| cascade | Worker-Kette (Pipeline) | Transformationsketten |
| ensemble | Mehrere Worker, Konsens nötig | Kritische Entscheidungen |
| dag | Graph-basiertes Scheduling | Komplexe Abhängigkeiten |

## 5. Datenmodell

```json
{
  "task_id": "string",
  "capability": "string",
  "strategy": "single | parallel | cascade | ensemble | dag",
  "workers": ["worker_id"],
  "cost_score": 0.0,
  "mreil_profile": {}
}
```

## 6. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Kein Worker verfügbar | Alle Worker ausgelastet | Queue + Retry |
| Capability nicht gefunden | Task-Anforderung unbekannt | Task ablehnen |
| Strategy nicht unterstützt | Ungültige Strategie | Fallback auf single |

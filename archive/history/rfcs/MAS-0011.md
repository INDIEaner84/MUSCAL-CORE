# MAS-0011: State Equivalence Layer (SEL) & Reducer Confluence Kernel

## 1. Motivation

MAS-0005 definiert deterministische Execution, aber keine formale Äquivalenzrelation über Systemzustände. Der verbleibende Gap ist algebraisch/semantisch: wir haben ein Event-System + Reducer, aber noch keine formale Äquivalenzrelation über Zustände. Damit fehlt die Closure-Ebene des Systems. SEL schließt diese Lücke.

## 2. Terminologie

| Begriff | Definition |
|---------|-----------|
| ℰ | Menge aller Events |
| S | Menge aller System States |
| canonical: S → S | CanonicalState-Funktion (Normierung) |
| ~ ⊆ S × S | Äquivalenzrelation: s1 ~ s2 ⇔ canonical(s1) = canonical(s2) |
| S/~ | Quotient Space (Zustandsäquivalenzklassen) |
| cl: 2^S → 2^S | Closure Operator — kleinste abgeschlossene Obermenge |
| Fold | Reduktionsfunktion: Event-Stream → State |

## 3. Systemmodell

Zwei Event-Streams sind äquivalent wenn ihre gefalteten Zustände äquivalent sind:

```
E1 ≈ E2 ⇔ Fold(E1) ~ Fold(E2)
```

## 4. Canonical State Function

Die Normalisierungsfunktion für Zustände:

1. Normalisiere Node-IDs (deterministisches UUID-Mapping)
2. Sortiere Adjazenzlisten (Graph-Kanonisierung)
3. Normalisiere Metadaten-Reihenfolge
4. Kollabiere kommutative Event-Effekte
5. Löse Version-Chains auf (nur letzte gültige Version)

## 5. Event Stream Equivalence

```
E1 ≈ E2 ⇔ Fold(E1) ~ Fold(E2)
```

Damit wird Event-Level-Vergleich auf State-Level reduziert.

## 6. Reducer Confluence Condition

Der Reducer muss garantieren: Unabhängigkeit von Event-Permutation innerhalb kausaler Ordnung.

### Formale Bedingung

```
Sei E partiell geordnet durch Kausalität (→)
Für alle linearen Erweiterungen L1, L2 von E:
Fold(L1) = Fold(L2)
```

### Commutativity Classes

| Klasse | Events | Verhalten |
|--------|--------|-----------|
| Kommutativ | MetadataPatched, EdgeCreated (distinkt), NodeCreated (distinkt) | Order-independent merge |
| Nicht-kommutativ | NodeUpdated (selber Node), RelationChanged, VersionOverride | Causal serialization erzwingen |

## 7. Snapshot Invariance Theorem (SIT)

Zwei Snapshots S(t1), S(t2) sind äquivalent genau dann wenn eine Bijektion f: Nodes(t1) → Nodes(t2) existiert, sodass:
- Struktur erhalten
- Relations-Graph erhalten
- Version-Chain-Äquivalenz gilt

## 9. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Nicht-kanonisierbarer State | Inkonsistente Daten | State invalid |
| Confluence violation | Reducer nicht deterministisch | Event-Stream zurückweisen |
| SIT mismatch | Snapshots inkonsistent | Rollback + Recompute |

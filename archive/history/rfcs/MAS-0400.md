# MAS-0400: Distributed Execution Fabric (Production System)

## 1. Motivation

MAS-0009 definiert die verteilte Execution Fabric auf Protokoll-Ebene. MAS-0400 erweitert dies um die Production-System-Aspekte: Sandbox, Policy, Governance und Container-Isolation. Dieses RFC formalisiert das MUSCAL Production System als lauffähige, sichere, überwachte Runtime-Infrastruktur.

## 2. Systemklassifikation

Das System ist NICHT:
- kein klassischer Agent
- kein Framework
- kein klassisches OS

Es ist ein: DAG-basiertes CI-System mit AI-Planer + closed-loop regression repair + execution firewall layer.

## 3. Drei Teilsysteme (Production System RFC A/B/C)

### RFC A — Formalisierung
- Spec-Layer (MBL) → Compiler → Execution Graph
- Deterministische Build-Kette

### RFC B — Podman Runtime
- Container-Isolation pro Agent
- Resource Limits (CPU, RAM, Network)
- Read-Only Root FS + Volumes

### RFC C — Distributed Fabric (erweitert)
- Multi-Orchestrator
- Verteilte Builds
- Federierte Konsensbildung

## 4. 6-Layer Production Stack

| Layer | Komponente | Aufgabe |
|-------|-----------|---------|
| L6 | UI / Dashboard | Steuerung & Visualisierung |
| L5 | API Gateway | Auth, Rate-Limit, Routing |
| L4 | Policy Engine | Capability-Check, Governance-Regeln |
| L3 | Sandbox | Process-Isolation, Resource-Limits (Podman) |
| L2 | Execution Graph | DAG-Runtime, VM (MAS-0300) |
| L1 | Storage / Persistence | SQLite, Snapshots, Backup (MAS-0100) |

## 5. Control Model

```
Input → Policy Gate → Resource Check → Sandbox Execution → Validated Output
```

## 6. Sandbox-Architektur (RFC B)

- Container-Isolation pro Agent (Podman)
- Resource Limits: CPU-Shares, RAM-Limit, Network-Block
- Read-Only Root FS mit beschreibbaren Volumes
- Kein direkter Host-Zugriff
- Deterministic Logging aller Container-Aktionen

## 7. Policy & Governance

- Rate-Limiting pro Capability
- Budget-Management (Token/Cost)
- Audit-Log + Compliance-Reporting
- Selbstheilung: Test → Diagnose → Patch → Rebuild (closed-loop)

## 9. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Sandbox escape | Container-Sicherheitslücke | Hard kill, Audit-Report |
| Policy violation | Regelverstoß | Execution reject, Log |
| Resource exhaustion | CPU/RAM-Limit überschritten | Graceful degradation |
| Spec-Runtime drift | Abweichung zwischen Spec und Ausführung | Recompile + Revalidate |

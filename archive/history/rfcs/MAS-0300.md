# MAS-0300: MAS Virtual Machine — Deterministischer Execution Simulator

## 1. Motivation

MAS-0005 definiert die Runtime-Semantik, aber keine virtuelle Maschine, die Execution deterministisch simuliert. Die MAS-VM spielt Execution-Graphen deterministisch ab (ohne LLM), berechnet Soll-Zustände und vergleicht sie mit Ist-Zuständen. Verwendung: Replay, Audit, Debug, Formal Verification.

## 2. Terminologie

| Begriff | Definition |
|---------|-----------|
| MAS-VM | Deterministische virtuelle Maschine |
| Instruction | Atomarer Schritt im Execution Graph |
| Program Counter | Aktuelle Position im Graph |
| Memory Page | Isolierter Speicherbereich |
| Trap | Unterbrechung (bei Fehler oder Capability-Verletzung) |

## 3. Systemmodell

```
Execution Graph → MAS-VM (deterministic) → Trace + State Snapshot
                 ↑ Seed, Context
```

Die VM garantiert: Gleicher Graph + Seed + Input → identischer Trace + Output.

## 4. VM-Architektur

### 4.1 Komponenten

| Komponente | Aufgabe |
|-----------|---------|
| Scheduler (VM-intern) | Node-Reihenfolge deterministisch festlegen |
| Executor | Node-Funktion ausführen (pure) |
| Memory Manager | Isolierten Context pro Node bereitstellen |
| Trace Recorder | Jeden Schritt aufzeichnen |
| Trap Handler | Fehler/Verstöße abfangen |

### 4.2 Instruction Set

| Instruction | Beschreibung |
|-------------|-------------|
| NOP | No operation |
| CALL node_id | Node ausführen |
| BRANCH condition | Bedingter Sprung |
| JOIN | Sync-Punkt |
| HALT | Execution beenden |

## 5. Execution Contract

```
Precondition:  Graph ist azyklisch, layer-konform, validiert
Execution:     VM traversiert Graph deterministisch
Postcondition: Trace + State Snapshot + MREIL Score
```

## 6. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Cycle detected | Graph enthält Zyklus | Trap, Execution abort |
| Missing capability | Node ohne Permission | Trap, Capability-Fehler |
| Non-deterministic output | Seed nicht eingehalten | Trace invalid |

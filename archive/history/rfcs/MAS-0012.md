# MAS-0012: Observability System — Trace, Replay & Diff Graph

## 1. Motivation

MAS-0005 definiert Execution Traces, aber kein vollständiges Observability-System. Dieses RFC formalisiert die vier Ebenen: Execution Graph → Trace Graph → Replay Graph → Diff Graph. Ziel: jede Ausführung vollständig nachvollziehbar, reproduzierbar und vergleichbar zu machen.

Das System beantwortet vier Fragen:
1. Was sollte passieren? (Execution Graph)
2. Was ist passiert? (Trace Graph)
3. Kann es reproduziert werden? (Replay Graph)
4. Warum unterscheiden sich zwei Ausführungen? (Diff Graph)

## 2. Gesamtübersicht

```
Execution Graph → Trace Graph → Replay Graph → Diff Graph
```

## 3. Terminologie

| Begriff | Definition |
|---------|-----------|
| Execution Graph | Soll-Zustand: geplante Node-Ausführung |
| Trace Graph | Ist-Zustand: tatsächlich ausgeführte Nodes |
| Replay Graph | Deterministische Wiederholung eines Trace |
| Diff Graph | Vergleich zweier Ausführungen |
| Snapshot | Eingefrorener Systemzustand |

## 4. Execution Graph

Der geplante Ausführungsgraph (MPIR) als Basis:

```json
{
  "nodes": [{"id": "n1", "operation": "retrieve", "layer": 2}],
  "edges": [{"from": "n1", "to": "n2"}],
  "expected_mreil": {}
}
```

## 5. Trace Graph

Der tatsächlich ausgeführte Graph:

```json
{
  "node_id": "n1",
  "status": "success | failed | skipped",
  "input_hash": "abc",
  "output_hash": "def",
  "duration_ms": 150,
  "seed": 42,
  "mreil_snapshot": {}
}
```

Trace Taxonomy: Jeder Node hat genau eines von: `success`, `failed`, `skipped`, `timeout`, `unknown`.

## 6. Replay Graph

Deterministische Wiederholung eines Traces mit identischem Seed:

```
Replay(input_trace, seed) → identical_trace iff determinism preserved
```

**Replay Contract:**
- Gleicher Input + Seed → identischer Output
- Alle Side Effects werden blockiert
- Timeout wird auf 0 gesetzt (kein Warten)

## 7. Diff Graph

Vergleich zweier Ausführungen (SEL-basiert):

| Dimension | Vergleichsgrundlage |
|-----------|-------------------|
| Structural | Graph-Struktur (Nodes, Edges) |
| Hash | Input/Output-Hashes |
| MREIL | Metrik-Vektoren |
| Temporal | Timing/Reihenfolge |

## 8. Snapshot-Regeln

- Snapshot wird erstellt bei: Run-Start, Run-Ende, Fehler
- Snapshot enthält: Trace Graph + MREIL Score + SEL Canonical State
- Retention: letzte 100 Snapshots, dann Kompaktierung

## 9. MREIL Extension

```yaml
mreil:
  trace_completeness: "percentage of fully traced nodes"
  replay_accuracy: "determinism preservation rate"
  diff_precision: "accuracy of state difference detection"
  snapshot_integrity: "checksum validation rate"
```

## 10. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Trace unvollständig | Log-Lücke | Incomplete flag, kein Replay |
| Replay mismatch | Nicht-deterministisch | Diff Graph generieren |
| Snapshot beschädigt | Speicherfehler | Vorherigen Snapshot laden |
| Diff inkonsistent | SEL-Fehler | Diff zurückweisen |

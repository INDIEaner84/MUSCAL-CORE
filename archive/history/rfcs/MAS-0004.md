# MAS-0004: MPIR Compiler & AST Transformation Layer

## 1. Motivation

Bisherige MAS-Schichten gehen davon aus, dass MPIR bereits existiert oder manuell erzeugt wird. Das ist nicht skalierbar. MAS-0004 definiert eine deterministische Compiler-Pipeline: Prompt → AST → Normalized AST → MPIR Graph.

## 2. Terminologie

| Begriff | Definition |
|---------|-----------|
| Source Prompt | Rohinput (textuell) |
| AST | Syntaktischer Baum |
| NAST | Normalisierter AST |
| MPIR | Ausführbarer Graph |
| Compiler Pass | Transformationsstufe |
| IR Node | Abstrakte Operationseinheit |

## 3. Compiler Pipeline

```
Prompt → Tokenize → Parse AST → Normalize AST → Validate Semantics → Compile MPIR Graph → Optimize Graph
```

## 4. AST Modell

```json
{
  "type": "root",
  "children": [
    { "type": "intent", "value": "query", "children": [] },
    { "type": "operation", "value": "retrieve", "children": [] }
  ]
}
```

## 5. Normalization Rules

### Regel 1 — Intent Canonicalization
Alle Synonyme → standardisierte Intent-Tags.

### Regel 2 — Operation Flattening
Verschachtelte Befehle → lineare IR Nodes.

### Regel 3 — Context Binding
Implizite Referenzen → explizite Graph Edges.

## 6. MPIR Compilation Mapping

| AST Element | MPIR Node Type |
|-------------|---------------|
| intent | control |
| operation | transform |
| memory reference | memory |
| conditional | branch |

## 7. Compiler State Machine

```
RAW_INPUT → TOKENIZE → PARSE_AST → NORMALIZE_AST → VALIDATE → COMPILE_MPIR → OPTIMIZE → OUTPUT_GRAPH
```

## 8. Optimization Rules

- Constant folding (static values)
- Node merging (redundant transforms)
- Dependency pruning
- Dead-node elimination

## 10. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Parse-Fehler | Ungültiger Prompt | Fehler-Event, Abbruch |
| Validierungsfehler | Semantisch inkonsistent | Normalisierung wiederholen |
| Optimierungsfehler | Graph nicht optimierbar | Unoptimierten Graph nutzen |

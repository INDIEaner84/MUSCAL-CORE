# MAS-0003: Context Graph Memory System

## 1. Motivation

MUSCAL benötigt ein persistentes, graph-basiertes Gedächtnis, das Kontext über mehrere Execution Cycles hinweg bewahrt. MAS-0003 definiert das Context Graph Memory als versionierten, event-sourced Graphen.

## 2. Terminologie

| Begriff | Definition |
|---------|-----------|
| Context Graph | Gerichteter Graph aus Knoten (Entities) und Kanten (Relationen) |
| Snapshot | Eingefrorener Zustand zu einem Zeitpunkt |
| Subgraph | Teilmenge des Graphen für eine Execution |
| Memory Query | Abruf von Kontext via Capability |

## 3. Systemmodell

```
Events → Memory Writer → Graph Store → Query API → RAG Context
```

Der Context Graph ist:
- **versioniert** (jeder Schreibvorgang erzeugt neue Version)
- **event-sourced** (alle Änderungen sind rekonstruierbar)
- **snapshot-fähig** (Zustand zu jedem Zeitpunkt abrufbar)

## 4. Architektur

### 4.1 Komponenten

| Komponente | Aufgabe |
|-----------|---------|
| Graph Store | Persistenter Speicher (SQLite/ChromaDB) |
| Memory Writer | Serialisierte Schreibvorgänge (CQRS) |
| Query API | Kontextabruf für Compiler + RAG |
| Snapshot Manager | Frozen States für Replay |

### 4.2 Datenmodell

```json
{
  "node_id": "string",
  "type": "entity | concept | event",
  "properties": {},
  "edges": [
    {"target": "node_id", "relation": "string", "weight": 0.0}
  ],
  "version": 1,
  "timestamp": "ISO-8601"
}
```

## 5. Fehlerfälle

| Fehler | Ursache | Reaktion |
|--------|---------|----------|
| Graph inkonsistent | Concurrent Writes | Rollback zur letzten Version |
| Query fehlgeschlagen | Index fehlt | Fallback auf Full Scan |
| Snapshot beschädigt | Speicherfehler | Vorherigen Snapshot laden |

# ADR-003: Capability-First statt Model-First

**Context:** MAS-0001 §3.1 fordert Capability-First, aber der bestehende Code in MUSCAL CORE routet teilweise noch model-basiert (z.B. `scheduler.py` prüft Modell-Namen). Zwei Alternativen: (a) Model-First beibehalten (einfacher, da bestehender Code), (b) vollständig auf Capability-First umstellen.

**Decision:** Wir stellen vollständig auf Capability-First um. Jeder Task wird gegen Capabilities geroutet, nicht gegen Modell-Namen. Der Scheduler wird capability-aware + MREIL-driven.

**Consequences:**
- + Modelle können jederzeit ausgetauscht werden (Replaceability Principle)
- + Scheduler kann optimal zwischen Modellen wählen
- + Neue Modelle benötigen keine Code-Änderungen im Router
- - Bestehender Code muss umgebaut werden (scheduler.py, bridge.py)
- - Capability Registry muss initial befüllt werden

**Rationale:** Model-First verstößt gegen MAS-0001 §3.1 und §3.5. Jedes Mal, wenn ein Modell ausgetauscht wird, müsste der Scheduler angepasst werden. Capability-First entkoppelt Modelle von der Routing-Logik komplett.

**Datum:** 2026-07-04
**Status:** ACCEPTED

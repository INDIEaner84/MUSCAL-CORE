# ADR-005: Kernel Interface Consolidation

**Context:** Das System hat mehrere Kernel-Instanzen:
`MuscalKernel` (`kernel.py`, 449 Zeilen) und `Kernel` (`kernel_core.py`,
77 Zeilen, bereits als DEPRECATED markiert). Dazu kommen `MinimalKernel`
(`minimal.py`/`minimal_core.py`), die keinen vollständigen Kernel darstellen.
Es gibt keinen gemeinsamen Vertrag — wer einen Kernel nutzt, muss die
konkrete Implementierung kennen.

**Decision:** Wir akzeptieren den Status Quo: `MuscalKernel` aus `kernel.py`
ist der einzige aktive Kernel. `kernel_core.Kernel` bleibt als
Referenz/Dokumentation. Wir definieren ein `KernelProvider` Protocol
in `interfaces.py` für zukünftige Plugins.

**Consequences:**
- + Ein einziger Kernel (MuscalKernel) reduziert Verwirrung
- + KernelProvider ermöglicht Plugin-Kernel in `features/`
- + kernel_core.py bleibt lesbar, aber nicht aktiv
- - Keine Runtime-Änderung an kernel.py (immutable)
- - Plugins müssen auf `MuscalKernel`-API aufbauen, nicht auf Protocol allein

**Rationale:** Die aktuelle Architektur ist stabil — `MuscalKernel` läuft
seit v0.7 ohne Fehler. `kernel_core.py` wurde nie fertiggestellt und ist
bereits dokumentiert als DEPRECATED. Ein Breaking Change an kernel.py lohnt
sich nicht, solange die API stabil ist.

**Datum:** 2026-07-08
**Status:** ACCEPTED
**Supersedes:** ADR-001 (Execution Graph Compiler) — betrifft andere Entscheidung,
dieses ADR-005 ist ein neues Thema.

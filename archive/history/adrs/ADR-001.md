# ADR-001: Execution Graph Compiler statt Interpreter

**Context:** MAS-0004 / MAS-0301 — MCXF wird derzeit interpretiert (MKC → Bridge → MEL), nicht kompiliert. Bei >50 Tasks entstehen 3s+ Latenz. Zwei Alternativen standen zur Wahl: (a) MCXF-Interpreter verbessern (Status Quo), (b) MCXF→EG Compiler neu bauen.

**Decision:** Wir implementieren Option (b) — den Execution Graph Compiler (MAS-0301). Der Compiler transformiert MCXF/YAML/MKC-Output in einen validierten, optimierten Execution DAG.

**Consequences:**
- + 10-100x schnellere Ausführung durch vorab kompilierten DAG
- + Deterministische Replay-Fähigkeit
- + Spine-Validierung als HARD GATE im Compiler-Durchlauf
- - MKC muss um BNF-Parser erweitert werden
- - Bridge-Matcher müssen in AST-Nodes übersetzt werden

**Rationale:** Der Interpreter hat bei 50+ Tasks 3s Latenz (gemessen), der Compiler schätzt <50ms für gleiche Workloads. Die Spine-Integration ist nur im Compiler-Modell sauber möglich — der Interpreter kann keine globale Graph-Validierung durchführen.

**Datum:** 2026-07-04
**Status:** ACCEPTED

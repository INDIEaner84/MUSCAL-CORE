### 3. Authoritative vs Optional Identifiers

| Identifier | Authoritative? | Optional? | Notes |
|------------|--------------|-----------|-------|
| execution_id | YES | NO | Required for execution-required events. Generated if not supplied. |
| event_id | YES | NO | Always generated by EventBus (uuid7). UNIQUE in EventStore. |
| correlation_id | NO | YES | User-supplied. Defaults to parent execution_id. Not validated. |
| causation_id | NO | YES | User-supplied. Defaults to parent execution_id. Heuristic in store_receipt/store_verification. |
| agent_id | NO | YES | Not propagated in current execution paths. |
| model_id | NO | YES | Not propagated in current execution paths. |
| trace_id | N/A | N/A | Not implemented in current architecture. |
| span_id | N/A | N/A | Not implemented in current architecture. |

### 5. Identity Loss or Weakness Points

| Point | Issue | Impact | Severity |
|-------|-------|--------|----------|
| `os.executed` event | Only includes `execution_id` and `execution_mode`. Missing `correlation_id`, `causation_id`, `verification_state`. | Identity incomplete for this event type. | LOW — not in execution-required topic set. |
| `EnrichedMuscalOS.run()` causation default | Defaults to `parent_ctx.execution_id` when not supplied — conflates causation with execution identity. | Causation chain may be imprecise when child specifies different causation than parent ID. | LOW — convention, not enforcement. |
| `_extract_identity` fallback | Missing `execution_mode` defaults to `"real"`, missing `verification_state` to `"unverified"`. | Silent defaults may mask missing wiring. | MEDIUM — should log warning. |

### 6. Certification Conclusion

**Identity Continuity: PASS**

Execution identity is preserved across ALL execution boundaries:
- ExecutionContext → EnrichedMuscalOS → MuscalOS → kernel → Graph → EventBus → EventStore
- No evidence of silent identity generation or replacement
- Two enrichment paths (_persist_to_store + _enriched_persist) both correctly propagate identity
- EventStore rejects execution-required events without execution_id
- Non-critical events (os.executed, os.started) have correct execution_id but may lack correlation/causation fields

Remaining weaknesses are documented and non-blocking for MC-TC-004.

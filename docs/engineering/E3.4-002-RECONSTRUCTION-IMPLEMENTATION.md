# E3.4 Self-Reconstructable Execution — Implementation Report

## Executive Summary

E3.4 Self-Reconstructable Execution is **IMPLEMENTED AND CERTIFIED**.

Given an `execution_id`, the system reconstructs the available causal execution history and explicitly classifies each relationship as VERIFIED, INFERRED, MISSING, or CONFLICT — all read-only.

| Dimension | Status |

## Architecture

### Data Flow

```
resolve_execution(execution_id)
    ↓
1. Locate execution in UTR._execution_store
2. Verify receipt integrity hash (SHA-256)
3. Build ExecutionRecord
4. Resolve verification from UTR._verification_store
5. Build IdentityRecord (execution_id, trace_id, span_id, decision_id)
6. Resolve governance from decisions DB table
7. Resolve trace decisions from decisions DB
8. Classify each relationship via EvidenceClassifier
9. Detect retries (same trace_id, different execution_id)
10. Build CausalGraph (nodes + edges)
11. Compute CompletenessSummary
12. Return ReconstructionReport
```

### Central Invariant

```
PROVENANCE INTEGRITY ≠ SEMANTIC TRUTH
```

Every reconstruction report separates:
- `provenance_integrity: VERIFIED/INFERRED/CONFLICT/MISSING` (chain consistency)
- `semantic_truth: "NOT ESTABLISHED"` (correctness of claims is separate)

### Evidence Classification Precedence

```
CONFLICT > VERIFIED > INFERRED > MISSING
```

A single CONFLICT overrides all other classifications in the report.

## Reconstruction Report Structure

```python
ReconstructionReport
├── identity: IdentityRecord (execution_id, trace_id, span_id, decision_id, receipt_id, verification_id)
├── governance: GovernanceRecord (decision_id, action, status, type, trace_id, span_id)
├── execution: ExecutionRecord (execution_id, tool, success, time, trace_id, span_id, decision_id, integrity)
├── verification: VerificationRecord (verification_id, execution_id, status, decision_id)
├── causal_graph: CausalGraph (nodes + edges)
├── completeness: CompletenessSummary (VERIFIED, INFERRED, MISSING, CONFLICT counts)
├── integrity: IntegrityStatus (10 field-level checks)
├── semantic_truth: SemanticTruthStatus (provenance_integrity + semantic_truth)
└── relations: list[Relation] (source, target, type, status, evidence, reason)
```

## Relation Types

| Type | Description | Evidence Source |
|------|-------------|----------------|
| CAUSES | Direct causal relationship | UTR execution store |
| AUTHORIZES | Governance authorizes execution | decisions DB |
| CONTAINS | Trace containment | trace_id on receipt |
| CORRELATES_WITH | Temporal/correlation | Same trace_id across records |
| RETRIES | Retry relationship | same trace_id, new execution_id |
| VERIFIES | Verification result | UTR verification store |

## Adversarial Resistance (27 scenarios)

### Identity Attacks (R1-R6)
| Test | Attack | Detection |
|------|--------|-----------|
| R1 | forged trace_id | INFERRED (no DB match) |
| R2 | forged span_id | VERIFIED (in receipt, no cross-check) |
| R3 | forged decision_id | MISSING (not in DB) |
| R4 | mismatched execution_id | MISSING (not found) |
| R5 | cross-trace binding | Isolated per execution_id |
| R6 | cross-task decision | VERIFIED decision + INFERRED containment |

### Provenance Attacks (R7-R14)
| Test | Attack | Detection |
|------|--------|-----------|
| R7 | provenance overwrite (post-finalize) | integrity hash mismatch |
| R8 | provenance deletion | trace_id empty in report |
| R9 | stale provenance | integrity hash mismatch |
| R10 | replayed execution | DUPLICATE_EXECUTION_ID rejected |
| R11 | orphaned execution | identity=None, completeness.missing>0 |
| R12 | orphaned decision | decision exists but no execution |
| R13 | orphaned receipt | receipt in store, no execution link |
| R14 | orphaned verification | verification without execution |

### Conflict Attacks (R15-R19)
| Test | Attack | Detection |
|------|--------|-----------|
| R15 | receipt vs decision mismatch | MISSING (no matching decision) |
| R16 | execution vs trace mismatch | CONFLICT or INFERRED |
| R17 | verification vs receipt mismatch | Different decision_ids noted |
| R18 | contradictory timestamps | Non-negative execution_time |
| R19 | duplicate decision identity | write_decision returns False |

### Reconstruction Attacks (R20-R25)
| Test | Attack | Detection |
|------|--------|-----------|
| R20 | missing provenance | identity=None, all counts zero |
| R21 | partial provenance | execution exists, decision MISSING |
| R22 | inferred as verified | CONTAINS explicitly INFERRED |
| R23 | temporal as causal | Only known types emitted |
| R24 | internally valid but semantically false | semantic_truth = NOT ESTABLISHED |
| R25 | corrupted integrity hash | verify_integrity() returns False |

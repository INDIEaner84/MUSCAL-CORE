# E3.3-002: Execution Provenance Identity Semantics

## Overview

Defines the exact semantics of `trace_id`, `span_id`, and `decision_id` — the three
provenance identifiers that provide end-to-end execution traceability and causal
reconstruction across the Muscal runtime.

## Core Identifiers

### trace_id

| Property       | Value                             |
|----------------|-----------------------------------|
| Type           | UUID v4 (hex string, 36 chars)    |
| Generator      | `kernel.run()` entry point        |
| Lifespan       | Entire execution trace (immutable)|
| Cardinality    | 1 per top-level invocation        |
| Visibility     | All spans, decisions, receipts    |

Generation point: `kernel.run()`, before any stage pipeline execution.
Passed via context dict as `ctx["trace_id"]`.

**Invariant**: Every `execution_id` in the trace belongs to exactly one `trace_id`.
No execution crosses trace boundaries.

### span_id

| Property       | Value                             |
|----------------|-----------------------------------|
| Type           | UUID v4 (hex string, 36 chars)    |
| Generator      | `UnifiedToolRuntime.execute()`    |
| Lifespan       | Single tool execution             |
| Cardinality    | 1 per `execute()` call            |
| Visibility     | ExecutionReceipt, all child decisions |

Generation point: `UnifiedToolRuntime.execute()`, at function entry before any
tool logic executes. Passed via `ctx["span_id"]`.

**Invariant**: Each `execution_id` maps to exactly one `span_id`. A `span_id` may
have zero or one `decision_id` (not all spans trigger governance decisions).
`span_id` is unique across the entire trace.

### decision_id

| Property       | Value                             |
|----------------|-----------------------------------|
| Type           | UUID v4 (hex string, 36 chars)    |
| Generator      | `GovernanceStage.process()`       |
| Lifespan       | Single governance decision        |
| Cardinality    | 0 or 1 per span                   |
| Visibility     | decisions table, ExecutionReceipt |

Generation point: `GovernanceStage.process()`, at each governance evaluation
(every pipeline iteration). Recorded in the `decisions` DB table.

**Invariant**: Every `decision_id` resolves to a valid record in `decisions`.
`decision_id` is unique across the entire system (UUID collision resistance).

## Provenance Binding

### Authority Chain

```
Orchestrator (kernel.run())
  └─ generates trace_id
  └─ passes via ctx["trace_id"]
      └─ UnfiedToolRuntime.execute()
          └─ generates span_id
          └─ passes via ctx["span_id"]
              └─ GovernanceStage.process()
                  └─ generates decision_id
                  └─ records to decisions table
                  └─ attaches to ctx["governance_decision_id"]
```

**Rule**: The provenance authority is strictly top-down. No component can
generate or modify a provenance identifier belonging to a higher level.
Agent code MUST NOT set `trace_id`, `span_id`, or `decision_id`.

### Causal Links

```
trace_id ──1:N── span_id ──0:1── decision_id
                                    │
                                    └── execution_id (UTR-owned)
```

Each `span_id` records its causal parent via the currently-active `span_id`
from the context. The first span in a trace has no parent.

## Retry Semantics

### trace_id
- **Same trace**: SAME trace_id
- **New invocation**: NEW trace_id

### span_id
- **Retry of same execution**: NEW span_id (each execute() call is a new span)
- **Causal parent**: Links to the triggering span

### decision_id
- **Same semantic decision** (e.g., re-allow under same policy): SAME decision_id
  (idempotent governance — reuse existing decision if policy unchanged)
- **New semantic decision** (e.g., policy changed, new evaluation): NEW decision_id
- **Retry with no re-evaluation**: SAME decision_id (carry forward)

### execution_id
- **Each execute() call**: NEW execution_id (always — UTR invariant)

## Temporal Ordering Constraint

For any execution trace, the following temporal ordering MUST hold:

```
trace_id.created_at  ≤  span_id.created_at  ≤  decision_id.created_at  ≤  execution_id.created_at
```

This ensures causal soundness: the trace exists before the span, the span
exists before any governance decision, and the decision exists before the
execution.

This is enforced via monotonic timestamps at generation time.

## Data Model Extensions

### ExecutionReceipt (added fields)
```python
trace_id: str | None = None
span_id: str | None = None
decision_id: str | None = None
```

### VerificationResult (added field)
```python
decision_id: str | None = None
```

### decisions table (upgraded schema)
```sql
-- New columns to add:
trace_id       TEXT REFERENCES traces(id),
span_id        TEXT,
decision_type  TEXT NOT NULL DEFAULT 'governance',
decision_status TEXT NOT NULL DEFAULT 'active',
governance_action TEXT,  -- 'allow', 'block', 'warn', 'escalate'

```

### Context dict keys
```python
ctx["trace_id"]    # Set by kernel.run()
ctx["span_id"]     # Set by UTR.execute()
ctx["decision_id"] # Set by GovernanceStage.process()
```

## Integrity Constraints

1. **Provenance-Authoritative**: The orchestrator (kernel.run()) is the sole
   generator of trace_id. UTR is the sole generator of span_id. GovernanceStage
   is the sole generator of decision_id. Agent-provided provenance is rejected.

2. **Non-Repudiation**: Every decision_id has a corresponding row in the
   decisions table. Every execution_id in a trace has a trace_id and span_id.

3. **Causal Completeness**: For any execution, the full chain
   trace_id → span_id → decision_id → execution_id can be reconstructed
   by joining (trace_id, execution_id in ExecutionReceipt) with
   (trace_id, decision_id in decisions table).

4. **Idempotency**: A governance decision with the same decision_id is
   not re-recorded. An execution with the same execution_id is not
   re-executed (existing UTR invariant).

## Non-Goals (Out of Scope for E3.3)

- `tool_call_id`, `artifact_id`, `request_id`, `edge_id` — reserved for
  future E3.x work packages.
- OpenTelemetry or external tracing systems — Muscal-native identifiers.
- Cross-service distributed tracing — single-process runtime scope.
- End-user query API for provenance — schema and storage only.

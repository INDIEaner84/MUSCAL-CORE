# E3.5.1 Evidence Enrichment Architecture

## Overview

E3.5.1 enriches the execution evidence chain with traceable identity,
first-class outcome semantics, append-only evaluation validation,
MREIL resource metrics, and epistemic boundary preservation.

## Components

### 1. Identity Enrichment

```
agent_id ──┐
model_id ──┤
execution_id ──┤── ExecutionReceipt ──→ integrity_hash (SHA-256)
trace_id ──┤
span_id ──┤
decision_id ──┘
```

- `agent_id` and `model_id` added to `ExecutionReceipt.__slots__`
- Included in `finalize()` hashing → immutable after finalization
- Unknown identity remains empty string (never fabricated)
- Cross-execution identity isolation verified

### 2. OutcomeRecord

First-class record distinguishing three outcome concepts:

```
OutcomeRecord
├── intended_outcome (SUCCESS/PARTIAL/FAILURE/UNKNOWN)
├── observed_outcome (from agent/evaluator)
└── verified_outcome (from independent evidence)
    └── outcome_status (resolved via merge_outcome_statuses)
    └── evidence_status (resolved via resolve_evidence_status)
```

- Technical execution success (`receipt.success`) is distinct from outcome success
- Agent claims → INFERRED evidence only
- Evaluator claims → INFERRED evidence only  
- Independent verification → can become VERIFIED
- `finalize()` makes immutable (SHA-256 integrity hash)

### 3. EvaluationValidation

Append-only validation artifact for meta-evaluation feedback:

```
EvaluationValidation
├── validation_id
├── evaluation_id
├── execution_id / trace_id / decision_id / outcome_id
└── validation_result (CONFIRMED/REFUTED/PARTIALLY_CONFIRMED/INCONCLUSIVE)
```

- Never rewrites historical evaluation records
- Integrity-hashed on finalize
- Distinct from outcome verification

### 4. MREIL Metrics

Non-fabricated resource measurements:

```
ResourceMetrics
├── latency (wall clock)
├── token_usage (counted, not estimated by ML)
├── cpu_time (process CPU time)
├── ram_peak (peak RSS)
├── cpu_percent
└── ram_current
```

- `psutil`-backed when available
- Graceful degradation when psutil unavailable
- Tokens manually counted via `add_tokens()`

### 5. Outcome Feedback Chain

```
Execution
→ Technical Result (ExecutionReceipt.success)
→ Outcome Observation (OutcomeRecord.update_observed)
→ Independent Verification (OutcomeRecord.update_verified)
→ Meta-Evaluation (existing MetaEvaluator)
→ Evaluation Validation (EvaluationValidation)
```

### 6. Epistemic Boundary

```
VERIFIED → VERIFIED (never downgraded)
INFERRED → INFERRED (never upgraded without independent evidence)
MISSING → UNKNOWN (never fabricated)
CONFLICT → CONFLICT (never silently resolved)
```

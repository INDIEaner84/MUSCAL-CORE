# E3.5 — Meta-Evaluation & Decision Quality Architecture

## Overview

E3.5 implements read-only meta-evaluation on top of E3.4 reconstruction.
The evaluation engine consumes `ReconstructionReport` evidence — not raw
uncontrolled agent claims — and produces a structured `MetaEvaluation` report.

Central invariant: **Evaluation is not evidence. Interpretation is not observation.**

## Data Flow

```
execution_id
    ↓
reconstruct_execution()   [E3.4]
    ↓
ReconstructionReport
    ↓
MetaEvaluator             [E3.5]
    ↓
MetaEvaluation
    ├── decision_quality
    ├── execution_quality
    ├── outcome_quality
    ├── causal_assessment
    ├── evidence_set[]
    ├── observations[]
    ├── interpretations[]
    ├── uncertainties[]
    ├── conflicts[]
    └── rationale
```

## Evaluation Dimensions

### Decision Quality

Evaluates the governance decision that authorized execution.

| Dimension | Source | Status |
|-----------|--------|--------|
| Authority compliance | GovernanceRecord.decision_type | AVAILABLE |
| Policy compliance | GovernanceRecord.governance_action | AVAILABLE |
| Evidence sufficiency | ReconstructionReport.completeness | AVAILABLE |
| Provenance completeness | ReconstructionReport.completeness | AVAILABLE |
| Decision consistency | IntegrityStatus | AVAILABLE |
| Constraint compliance | GovernanceRecord.reasoning | PARTIALLY_AVAILABLE |
| Risk awareness | N/A | NOT AVAILABLE |
| Resource efficiency | N/A | NOT AVAILABLE |
| Task fit | N/A | NOT AVAILABLE |

### Execution Quality

Evaluates the execution itself.

| Dimension | Source | Status |
|-----------|--------|--------|
| Execution success | ExecutionRecord.success | AVAILABLE |
| Policy compliance | GovernanceRecord.governance_action | AVAILABLE |
| Trust-boundary compliance | IntegrityStatus | AVAILABLE |
| Provenance integrity | ExecutionRecord.integrity_valid | AVAILABLE |
| Verification result | VerificationRecord.status | AVAILABLE |
| Retry behavior | Relations with RETRIES | AVAILABLE |
| Resource efficiency | ExecutionRecord.execution_time | PARTIALLY_AVAILABLE |
| Latency | ExecutionRecord.execution_time | AVAILABLE |
| Failure handling | Relations | PARTIALLY_AVAILABLE |
| Determinism | N/A | NOT AVAILABLE |

### Outcome Quality

Evaluates the outcome only where evidence exists.

| State | Definition |
|-------|------------|
| SUCCESS | Verification passed, expected_state matches actual |
| PARTIAL | Some verification criteria met |
| FAILURE | Verification failed or execution failed |
| UNKNOWN | No outcome evidence available |

## Epistemic Status Preservation

```
E3.5-B01 — Epistemic Status Escalation
```

The evaluator may interpret evidence but may NOT increase its epistemic status
without new independent evidence.

Prohibited:
- INFERRED → VERIFIED
- MISSING → VERIFIED
- UNKNOWN → VERIFIED
- CONFLICT → VERIFIED

The evaluation layer preserves the distinction between:
- `evidence status` (what the data says)
- `evaluation conclusion` (what the evaluator infers)

## Causal Assessment

| Level | Definition | E3.4 Support |
|-------|------------|--------------|
| CAUSALLY_SUPPORTED | Direct CAUSES relation in reconstruction | RelationType.CAUSES |
| TEMPORALLY_ASSOCIATED | Temporal ordering known | RelationType.PRECEDES |
| CORRELATED | Same trace/correlation | RelationType.CORRELATES_WITH |
| INFERRED | Derived from structural reasoning | INFERRED status relations |
| UNKNOWN | No evidence | MISSING status |

## Hard Boundaries

E3.5 MUST NOT:
1. Rewrite historical provenance
2. Modify past decisions
3. Modify trust boundaries automatically
4. Upgrade INFERRED evidence to VERIFIED
5. Treat correlation as causation
6. Hide uncertainty
7. Retroactively rewrite execution history
8. Self-authorize policy changes
9. Automatically alter governance
10. Treat its own evaluation as authoritative truth

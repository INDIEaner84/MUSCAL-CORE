### 1.2 ExecutionReceipt + Verification
- **File:** `features/tool_runtime/tool_runtime.py`
- **Changes:**
  - `VerificationResult` — enum: PENDING, EXECUTED, VERIFIED, FAILED, NOT_VERIFIABLE
  - `ExecutionReceipt` — id, tool_name, args, result_data, execution_time, verification status
  - `UnifiedToolRuntime.register_verifier()` — register per-tool verification function
  - `UnifiedToolRuntime.verify()` — verify by receipt_id, tool_name, or all
  - `UnifiedToolRuntime.receipts()` / `receipt()` — receipt query API
  - `ToolResult.receipt` — receipt attached to every result
  - Verifiers registered: `math.add` (recomputation), `filesystem.write` (file read-back), `browser.screenshot` (file existence), `opencode.run` (status check)
- **Verification lifecycle:** PENDING → EXECUTED (after execute, verifier registered) → VERIFIED (after verify passes) / FAILED (verification fails or exception) / NOT_VERIFIABLE (no verifier registered)
- **Receipt generated for:** successful execution, executor exception, unknown tool, safety-gate blocked

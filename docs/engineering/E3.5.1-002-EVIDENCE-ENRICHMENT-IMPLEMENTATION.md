## Outcome Model Semantics

```python
# Three distinct concepts:
intended_outcome  # What was planned/expected
observed_outcome  # What was reported (agent/evaluator)
verified_outcome  # What was independently verified

# Resolution rules:
merge_outcome_statuses([FAILURE, ...]) → FAILURE
merge_outcome_statuses([PARTIAL, ...]) → PARTIAL
merge_outcome_statuses([SUCCESS, UNKNOWN]) → PARTIAL
merge_outcome_statuses([SUCCESS, SUCCESS]) → SUCCESS
merge_outcome_statuses([UNKNOWN, UNKNOWN]) → UNKNOWN

resolve_evidence_status([CONFLICT, ...]) → CONFLICT
resolve_evidence_status([MISSING, ...]) → MISSING
resolve_evidence_status([INFERRED, ...]) → INFERRED
resolve_evidence_status([VERIFIED, ...]) → VERIFIED
```

## Key Design Decisions

1. **No executor leakage**: `model_id` is a data field, not a callable
2. **No fake provenance**: Unknown identity stays empty
3. **Immutability**: `finalize()` locks all OutcomeRecord/EvaluationValidation fields
4. **Append-only**: New evidence creates new records; history is never rewritten
5. **Epistemic honesty**: Agent/evaluator claims are never auto-upgraded to VERIFIED
